## Как получены наблюдения

Игра запущена штатным скриптом. Управление выполнялось одиночными касаниями, свайпами, возвратом Android и вводом имени. После значимых переходов сохранён PNG всего экрана. Скриншоты просмотрены, а не интерпретированы только по текстовым названиям контролов.

Промежуточная выгрузка Android UI-дерева иногда возвращала старый диалог вместо актуального экрана. Поэтому она исключена из доказательной базы; в каталоге оставлены только PNG. Для симуляционной области текстовое дерево в любом случае не описывает клеточную динамику.

Нажатие на Cell synthesizer в Algae и затем на чашку подтверждается последующим увеличением счётчика вставок. Причина исчезновения клетки не установлена. Между кадрами проходило реальное время; скриншоты не служат измерением скорости симуляции.

## Если подключать человека: протокол записи по задачам

Это необязательный способ дополнить исследование, особенно для поздней игры и сложных организмов.

1. Выбрать **один сценарий на запись**: например, «создать двухклеточный организм, сохранить и восстановить». Зафиксировать версию, доступные гены и стартовое состояние.
2. Снять непрерывное видео от точки входа до результата. Для жестов полезно включить показ касаний. Делать ключевые скриншоты до действия, после ответа и при ошибке.
3. Комментировать намерение: «хочу, чтобы дочь двигалась», ожидание и увиденный результат. Не ограничиваться перечислением кнопок.
4. Пройти успешную ветку, затем одну ошибку/отмену/возврат. Для сохранения обязательно выйти и открыть результат снова.
5. Менять один параметр за раз. В записи отмечать игровое время; ускорение и паузы назвать явно. Для чувствительных к случайности опытов повторить старт.
6. Приложить исходный и итоговый геном/среду, если доступен локальный экспорт. Не выдавать одинаковый скриншот за доказательство идентичности сохранений.
7. Итог каждого прохода оформить краткой карточкой ниже. Фиксировать неизвестное прямо; один проход не доказывает универсальное правило.

## Критерий готовности следующего уточнения

Правило можно считать восстановленным для конкретного контекста, когда есть воспроизводимый старт, выполненное действие, наблюдаемый результат и проверка существенной альтернативной ветки. Полное прохождение кампании не требуется для описания навигации, но требуется дополнительное доказательство для каждой заявляемой поздней механики и её баланса.
