# Автоматические решения испытаний

Демонстрация выполняет те же действия, что доступны игроку. Бюджет постановок,
список инструментов, разрешённые типы, ограничения числа слотов заданного типа и
лимит удалений проверяются в движке (`simulation/level/rules.rs`).

- Новая клетка имеет обычную начальную массу 1. Поле `mass` не может её увеличивать.
- Нулевой бюджет запрещает постановки. `add` означает подкормку, а не бесконечные вставки.
- Удаление, подкормка и перенос требуют соответствующих инструментов уровня.
- Бюджет расходуют успешные действия; гибель или удаление клетки не возвращают вставку.
- Все режимы генома, включая дочерние и неиспользуемые, должны иметь разрешённые типы.
- Решение стартует с исходной сцены и seed. Ошибка действия останавливает демонстрацию,
  показывает причину и считается провалом проверки. Действие не игнорируется молча.

## Содержание и воспроизведение

Источник авторских решений — `levels/solutions/index.json`. В нём геномы
используют локальные индексы, которые `scripts/level_solutions.py` смещает при
добавлении к исходным геномам уровня. `scripts/build_levels.py` сохраняет эти
решения при регенерации и не создаёт сценарии с произвольной массой или лишними вставками.

Обычные `levels/<id>.json` самодостаточны: браузеру реестр не нужен. Субстрат,
числовые цели, доступные инструменты, разрешённые типы и бюджет оставлены прежними.

В интерфейсе предлагаются только решения со статусом `verified`, реально доведённые
до победы. Нулевое число действий допустимо: игроку показывается ожидание естественного
развития сцены. Геном первой постановки загружается в редактор, чтобы его можно было
изучить и воспроизвести вручную.

Статус `unavailable` явно означает отсутствие подтверждённого решения. У такого уровня
нет автоматической дорожки; вместо ложного прохождения показана причина. Сам уровень
и подсказки остаются доступны. Тест отдельно фиксирует наличие уже подтверждённых
решений: замена рабочего решения на `unavailable` не может незаметно сделать проверки зелёными.

## Проверки

```sh
# Правила, инструменты, бюджеты и эквивалентность ручной постановки/демо.
bash scripts/rust.sh test -p cellhub-simulation --lib level::

# Все дорожки проверяются на ограничения; каждое предлагаемое решение — на победу.
LEVEL_JOBS=3 bash scripts/rust.sh test -p cellhub-simulation --test levels -- --nocapture

# Регенерация не меняет исходные лимиты, сцену и решения.
python3 scripts/level_solutions_test.py

# Реальное проигрывание всех доступных решений в WASM и проверки бюджета через ABI.
npm run build:wasm
node scripts/game.test.mjs

# Подробная диагностика одного уровня.
bash scripts/rust.sh run --release -p cellhub-simulation --example level_check -- 1
LEVEL_TRACE=1 LEVEL_CENSUS=10 ./target/release/examples/level_check 1
```

`LEVEL_PATH=/path/to/candidate.json` позволяет проверить кандидат, не перезаписывая
игровой манифест. `LEVEL_LIMIT` ограничивает симулированное время. Тест кампании
имеет отдельный лимит 30 секунд реального времени на каждый уровень.

## Критерий улучшения

Приоритет — меньше разрешённых вмешательств, затем время достижения цели. Для
целей с клетками игрока одно начальное размещение является нижней границей, когда
в исходной сцене нет клеток игрока. Нулевые дорожки оптимальны по числу вмешательств.
Для составных решений удалялись лишние действия с повторным прогоном; математическая
глобальная оптимальность остальных геномов не заявляется.

Не меняйте условия или ресурсы ради прохождения. Если сценарий не проходит,
сохраняйте его неподтверждённым и фиксируйте препятствие в [аудите](level-solutions-audit.md).
