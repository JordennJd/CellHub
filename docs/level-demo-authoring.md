# Авторинг демо уровней

Демо — это доказательство, что уровень действительно проходим: тест
`crates/simulation/tests/levels.rs` загружает JSON так же, как браузер, запускает
`demo` в реальной симуляции и требует победы. Демо не обязано повторять путь
игрока; это может быть любой сценарий, который честно выполняет условия уровня.

## Быстрый цикл

```bash
# Проверить один уровень (release-бинарь уже собран).
./target/release/examples/level_check 11

# Подробно: события спавнов/смертей/делений/инфекций/целей.
LEVEL_TRACE=1 ./target/release/examples/level_check 11

# Периодический срез субстрата (раз в 10 секунд).
LEVEL_CENSUS=10 LEVEL_VERBOSE=1 ./target/release/examples/level_check 11

# Увеличить/уменьшить бюджет симулированного времени.
LEVEL_LIMIT=600 ./target/release/examples/level_check 11

# На провале вывести все живые клетки (осторожно: большой JSON).
LEVEL_CELLS=1 ./target/release/examples/level_check 11
```

Тест даёт каждому уровню **30 реальных секунд**. Release-бинарь обычно
проходит уровень за доли секунды, поэтому цель — уверенная победа с запасом.
Если демо не укладывается в `max-time` или требует больше ~20 секунд
симулированного времени, лучше упростить стратегию.

Полный прогон (не запускать параллельно с другими агентами):

```bash
cargo test -p cellhub-simulation --test levels
```

## Что можно менять

Редактируйте **только назначенные JSON-файлы** в `levels/`. Не запускайте
`scripts/build_levels.py` (он перегенерирует все уровни), не меняйте Rust,
не трогайте чужие уровни, не делайте git-коммиты.

Предпочтительный порядок:

1. Понять условие и подсказку из JSON (`hints`, `solution`).
2. Найти страницу уровня на
   [Cell Lab Wiki → Category:Challenge](https://cell-lab.fandom.com/wiki/Category:Challenge)
   и прочитать готовое решение. Название уровня в JSON русское; ищите по
   номеру/смыслу (например, «Противодействие» = Counteraction).
3. Собрать демо из уже имеющихся в уровне геномов.
4. Если готового генома не хватает — добавить в `genomes` новый геном
   (назовите его `Demo Solution` / `Решение`) и спавнить его в демо.
   Оригинальные геномы не удаляйте и не ломайте: уровень должен оставаться
   играбельным для человека.
5. Проверить `level_check`, при необходимости менять геном/демо и повторять.

Если уровень кажется непроходимым из-за механики движка, остановитесь и
сообщите: номер уровня, что именно не работает, минимальный воспроизводящий
`LEVEL_TRACE=1` вывод. Не маскируйте проблему подгонкой условий.

## Формат уровня

Верхний уровень (все имена полей — camelCase):

```jsonc
{
  "schema": 1,
  "id": "11",
  "order": 21,
  "title": "…",
  "description": "…",
  "difficulty": 3,
  "hints": ["…"],
  "solution": "…",
  "tools": ["place", "select"],
  "budget": 2,
  "removeMax": null,
  "maxCellsOfType": {},
  "allowedKinds": [],
  "tutorial": false,
  "environment": { "light": 1, "food": 1, "radiation": 0.3, "viscosity": 150,
                   "aging": true, "killAtEdge": false, "onlyPointMutations": true,
                   "gravity": 0, "density": 0, "nitrogen": 1, "maxCells": 800 },
  "terrain": { "light": 0.8, "lightRange": 1, "radiation": 0, "food": 0.5,
               "capacity": 1, "nitrates": 1, "biome": 0 },
  "conditions": { "user-cells": 420 },
  "genomes": [ { "version": 5, "modes": [ … ] } ],
  "initial": { "cells": [ … ], "links": [[0, 1]], "food": [[x, y, size]] },
  "demo": [ { "at": 0, "op": "spawn", "x": 0.5, "y": 0.2,
              "genome": 3, "mode": 0, "mass": 1.4 } ],
  "test": { "seed": 1234, "maxSeconds": 220 }
}
```

### Условия

| Ключ | Смысл |
|---|---|
| `user-cells` | ровно/минимум пользовательских клеток (класс 1) |
| `user-cells-max` | не больше пользовательских клеток |
| `level-cells` | максимум клеток субстрата (класс 0 + 3) |
| `level-cells-min` | минимум клеток субстрата |
| `total-cells-min` | минимум всех клеток |
| `infected-level-cells` | минимум заражённых (класс 3) |
| `infected-level-cells-max` | максимум заражённых |
| `hybrid-cells-min` | минимум гибридов (класс 6) |
| `black-level-cells` | максимум чёрных клеток субстрата |
| `red-level-cells` | максимум красных клеток субстрата |
| `red-level-cells-min` | минимум красных клеток субстрата |
| `yellow-level-cells` / `yellow-level-cells-min` | то же для жёлтых |
| `win-time` | сколько секунд все положительные условия должны держаться |
| `max-time` | жёсткий дедлайн; после него — поражение |

`*-max` — это ограничения: их нарушение сразу проигрывает. Положительные
условия должны выполняться одновременно в течение `win-time`. Цветовые
условия считают **только клетки класса 0** (субстрат), не пользовательские.

Пороговые цвета: чёрный — сумма компонент < 0.1; красный —
`R>0.65, G<0.35, B<0.35`; жёлтый — `R>0.65, G>0.65, B<0.35`.

### Классы клеток

| class | Значение |
|---|---|
| 0 | субстрат (стартовые клетки уровня) |
| 1 | пользовательская (спавн демо/игрока) |
| 3 | заражённая |
| 6 | гибрид |

`maxCells` — жёсткий лимит популяции: когда мир заполнен, деления и спавны
прекращаются. Для целей «вырастить N клеток» нужно либо оставить запас, либо
уничтожать/выедать клетки субстрата.

### Геном

```jsonc
{ "version": 5, "modes": [
  { "name": "Demo", "kind": 1, "threshold": 1.4, "canDivide": true,
    "childA": 0, "childB": 1, "bindChildren": true, "keepAdhesionA": true,
    "red": 1.0, "green": 0.2, "blue": 0.2 }
] }
```

`childA`/`childB` по умолчанию указывают на собственный индекс. Цвета по
умолчанию берутся из типа клетки. Все поля, кроме `kind`, опциональны и имеют
дефолты (см. `schema.rs`).

Типы клеток (`kind`):

| kind | Тип | Назначение |
|---|---|---|
| 0 | Photocyte | фотосинтез |
| 1 | Phagocyte | ест еду/клетки |
| 2 | Flagellocyte | плавание |
| 3 | Virocyte | заражает |
| 4 | Keratinocyte | защита |
| 5 | Devorocyte | хищник, съедает клетки |
| 6 | Nitrocyte | азот |
| 7 | Lipocyte | жир/еда |
| 8 | Buoyocyte | плавучесть |
| 9 | Glueocyte | слипание |
| 10 | Stereocyte | чувство цвета |
| 11 | Senseocyte | чувство типа клетки |
| 12 | Myocyte | сокращение |
| 13 | Neurocyte | сигналы |
| 14 | Secrocyte | секреция |
| 15 | Stemocyte | дифференциация |
| 16 | Gamete | половая клетка |
| 17 | Ciliocyte | реснички |

Полезные поля режима: `threshold` (масса для деления),
`ratio` (доля массы дочерней A), `speed` (0..60), `angle`, `lifespan`,
`maxConnections` (−1 = без лимита), `bindChildren`, `keepAdhesionA/B`,
`childAngleA/B`, `mirrorA/B`, `density`, `signalChannel`, `sensor`,
`sensorGain`, `transitionA/B` + `transitionThresholdA/B`, `offspringMode`,
`compatibleMode`, `virusCopyFrom`, `programs`.

`programs` — до 8 уравнений на режим:

```jsonc
{ "target": 8, "input": 12, "kind": 0, "scale": 4, "offset": 0 }
```

`target`: 0..7 — сигналы, 8 — скорость, 9 — плотность, 10 — сокращение,
11 — изгиб, 12 — подъём, 13/14 — левые/правые реснички, 15 — скорость
секреции, 16/17 — дифференциация A/B. `input`: 0 — константа 1, 1..8 —
сигналы, 9 — масса, 10 — возраст, 11 — азот, 12 — число связей,
13 — `sin(age)`. `kind`: 0 — `offset + scale*value`, 1 — порог
(`value < threshold ? below : offset + scale*value`).

### Демо

Действия выполняются, когда симулированное время достигает `at` (секунды).
Держите массив отсортированным по `at`.

```jsonc
{ "at": 0,    "op": "spawn", "x": 0.28, "y": 0.22, "genome": 3, "mode": 0, "mass": 1.4 }
{ "at": 2.5,  "op": "boost", "id": 1 }
{ "at": 5.0,  "op": "remove", "id": 2 }
```

- `x`,`y` — нормализованные координаты чашки (0..1), `y=0` — верх.
- `genome` — индекс в массиве `genomes`, `mode` — индекс режима.
- `mass` — стартовая масса; слишком маленькая клетка может погибнуть.
- `id` для `remove`/`boost` — id существующей клетки. Стартовые клетки
  получают id 1..N в порядке массива `initial.cells`; id спавнов
  предсказуемы, но зависят от делений, поэтому лучше адресовать только
  стартовые клетки.

Спавн отклоняется, если достигнут `maxCells` — в `LEVEL_TRACE` это видно как
`spawn ... id=0`.

## Диагностика

`level_check` печатает:

- `state`, `elapsed`, `counts` по классам и цветам;
- `conditions` — текущее/целевое значение и `ok`/`FAIL`;
- `census` — ресурсы субстрата, группы клеток по `class/mode/color`, массу,
  центроид, поколения и мутации;
- события: `load`, `demo-start`, `demo spawn`, `birth`, `divide`, `death`,
  `infection`, `fusion`, `remove`, `boost`, `objective`, `state`.

Если что-то не сходится, сначала смотрите `LEVEL_TRACE=1`:

- `demo spawn ... id=0` — спавн отклонён лимитом популяции;
- нет `birth` — геном не делится (мало массы/азота, `canDivide`, лимит связей);
- клетки класса 1 быстро исчезают — голод/токсины/выедание;
- `objective ... met` мерцает — условие не держится `win-time`;
- цвет в census не тот — проверьте `red/green/blue` режима и пороги.

## Критерий готовности

1. `./target/release/examples/level_check <id>` печатает `WON`.
2. Победа наступает с запасом по симулированному времени (лучше ≤ 75% от
   `max-time`/`test.maxSeconds`).
3. Уровень остаётся осмысленным для игрока: стартовые условия, подсказки и
   доступные инструменты не переписаны под демо.
4. Изменены только назначенные JSON-файлы.
