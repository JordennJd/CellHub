# CellHub

Изменения по датам: [история изменений](CHANGELOG.md).

Общий PoC объединяет React-редактор многоклеточного генома и Rust/wgpu-отрисовку мира через WebGPU или WebGL2.
Редактор, панели и оформление находятся в React; `crates/frontend` рисует только
мир, а симуляция Rust/hecs работает в Worker. Опционально тот же Rust-мир может
исполняться на авторитарном сервере и транслироваться в публичные комнаты по
WebSocket; редактор генома при этом остаётся локальным у каждого игрока.
Подробности: [гибридная архитектура](docs/rust-frontend.md) и
[сетевой режим](docs/multiplayer.md).

Локальная веб-песочница искусственной жизни: React/TypeScript управляет интерфейсом, Rust/wgpu и WGSL-шейдеры рисуют субстрат и клетки с инстансингом, Rust nightly + hecs ECS исполняет симуляцию в Web Worker через WebAssembly. Один и тот же рендерер работает через WebGPU, а при его недоступности — через WebGL2 (GL-бэкенд wgpu и трансляция WGSL в GLSL).

Для дальнейшей разработки: [пути игрока в оригинальной Cell Lab v103](docs/original-game/README.md) — наблюдения в Android-эмуляторе, карта экранов, функциональные правила, скриншоты и сравнение с текущим POC. Подтверждённое поведение отделено от предложений для веб-версии и непроверенных веток.

## Запуск

Нужны Node.js 22.12+ (или 24+), Rustup и закреплённый `rust-toolchain.toml` toolchain. Rustup автоматически установит nightly и цель WASM. Для Nix: `nix develop`.

```sh
npm ci
cargo install wasm-bindgen-cli --version 0.2.130 --locked
npm run build:wasm
npm run build:rust-frontend
npm run dev
```

Открыть адрес Vite (обычно http://127.0.0.1:5173). На этом компьютере Rust и CLI установлены локально в `.tools/`; сборщик поддерживает эту установку, обычный Cargo и явный `CARGO_HOME`. `./start.command` собирает оба WASM-модуля и запускает Vite. Первичная установка зависимостей обязательна; в терминале должен быть активен Node.js 22.12+ (например, `nvm use 22`).

Если установлен [just](https://github.com/casey/just) (он входит в Nix devShell), те же шаги выполняет `just dev`: при необходимости ставит npm-зависимости, автоматически устанавливает `wasm-bindgen-cli` 0.2.130 в `.tools/wasm-bindgen`, собирает WASM и запускает Vite. Без аргументов `just` запускает `just dev`. Список рецептов — `just --list`.

`just install-hooks` включает git-хук, который перед коммитом проверяет форматирование Rust через `cargo fmt --check` и порядок модулей в `crates/` через `just check-order`. Отформатировать код — `just fmt`.

Production-сборка деплоится на тестовый сервер через `just deploy <host> [ssh-port]`. Адрес сервера не хранится в репозитории и передаётся аргументом. Внутри сервера статика раздаётся по HTTP на порту 8081, откуда её забирает внешний reverse-proxy.

```sh
npm run build       # WASM + TypeScript + production bundle в dist/
npm test            # Rust + модель генома + библиотека/прогресс + WASM + сервер
npm run test:rust   # проверки симуляции и подготовки данных рендерера
npm run test:model  # модель редактора и миграции генома
npm run test:game   # библиотека, прогресс, все восемь решений испытаний
npm run test:wasm   # проверки настоящего WASM и очереди команд
npm run test:server # комнаты, чанки и серверные команды
npm run check       # проверка TypeScript (после сборки WASM)
npm run preview     # production-версия после npm run build
```

`dist/` можно раздавать любым статическим HTTP-сервером с MIME `application/wasm`. Web Worker и WASM не загружаются через `file://`. COOP/COEP не требуются: SharedArrayBuffer пока не используется. Canvas рисуется через Rust/wgpu. При загрузке приложение пытается запустить WebGPU; при ошибке автоматически переключается на WebGL2. Технический переключатель не показывается в игровом интерфейсе; для диагностики принудительный WebGL доступен через `?renderer=webgl`, а активный бэкенд — в атрибуте `data-renderer` канваса. Android поддерживается как адаптивная веб-страница, не APK; на устройстве пока не проверено.

Код сервера, протокола и сетевого клиента получен из main. Подключение мультиплеера к текущему меню и расширенному формату генома отложено; «Арена» пока недоступна. Сервер можно проверять отдельно через `npm run test:server`.

## Как пользоваться

1. На стартовом экране выберите **Обучение**, **Испытания** или **Песочницу**. Здесь же открываются сохранённые эксперименты, банк геномов и настройки. «Хаос» и «Арена» показаны равноправными, но отключёнными карточками. Обучение и «Ваши работы» вынесены в отдельные панели.
2. Три урока охватывают микроскоп, редактор генома и многоклеточный организм. Восемь адаптированных испытаний проверяют рост, питание, связи, разделение ролей, выживание, хищничество и передачу генома. У них есть проверяемые условия, лимит вставок, подсказка, решение и последовательное открытие. Это не полная оригинальная кампания Cell Lab.
3. В лаборатории слева находится чашка, справа — панели **Геном**, **Наблюдение**, **Среда** и, для учебного режима/испытаний, **Задача**. Время изначально на паузе. Доступны продолжение, один шаг, скорости 1×/2×/4× и перезапуск.
4. Выберите инструмент **Поместить**, чтобы создать клетку с текущим геномом и явно выбранным начальным режимом. **Диагностика** выделяет клетку и показывает её параметры, не заменяя черновик редактора. Отдельная кнопка копирует геном выбранной клетки в редактор. В песочнице также доступны перенос выбранной клетки, подпитка, удаление и применение генома редактора к выбранной клетке.
5. На ПК левая кнопка использует активный инструмент, правая выбирает клетку; зажатое колёсико или инструмент **Обзор** перемещает карту. Колесо меняет масштаб. В режиме размещения удержание левой кнопки от одной секунды повторяет вставки каждые 200 мс. На сенсорном экране касание использует инструмент, перетаскивание перемещает карту, щипок меняет масштаб. **Вся чашка** возвращает обзор всей карты.
6. Редактор позволяет добавлять, переименовывать, копировать и удалять режимы, независимо выбирать начальный режим, настраивать тип клетки, деление, дочерние режимы, распределение массы, угол деления, направления и зеркальность дочерей, RGB-цвет, связи, подвижность и срок жизни. Числа можно вводить напрямую или ползунком; рядом есть объяснения. **Предпросмотр развития** показывает организм до возраста 60 секунд в отдельной среде и не меняет клетки основной чашки.
7. На панели **Среда** в песочнице изменяются свет, питание, радиация, вязкость, старение, гибель на границе, гравитация, плотность и ограничение мутаций точечными. В испытаниях условия фиксированы. Переключатель слоя над чашкой меняет только отображение. **Стерилизовать чашку** удаляет клетки и связи, сохраняя среду и её возраст; **Начать заново** сбрасывает мир и время, оставляя геном редактора.
8. **Сохранить геном** сохраняет именованную конструкцию; **Сохранить эксперимент** — состояние мира, среду, время и геном редактора. Библиотеки поддерживают открытие, переименование, удаление и экспорт/импорт JSON. Старый одиночный геном автоматически переносится в банк отдельной записью; его исходная запись остаётся нетронутой. Файлы оригинальной Android Cell Lab не поддерживаются.
9. В настройках доступны подтверждения выхода/сброса и пауза при переключении вкладки. Сохранения хранятся в текущем браузере; для резервной копии или переноса экспортируйте файл.

Готовый многоклеточный пример находится в редакторе под **Начать с готового генома**: M1-фотоцит → связанные M2-жгутикоцит и M3-фагоцит. M2 не делится; M3 порождает M3 с прежними связями и отдельный M1. Замена примера затрагивает только черновик редактора. Подробнее: [геном и адгезия](docs/multicellular-genome.md).

Текущий объём переноса и оставшиеся отличия: [статус веб-адаптации](docs/web-migration-status.md). **DoD «весь функционал Cell Lab» пока не выполнен.**

## Реализованные механизмы

- Карта 3072 × 3072, 48 × 48 ресурсных участков, четыре hardcoded-биома. Участки хранят свет, радиацию и истощаемую/восстанавливаемую пищу.
- Шесть типов: Photocyte (свет), Phagocyte (пища), Flagellocyte (движение), Virocyte (контактное копирование генома), Keratinocyte (пониженный метаболизм, защита себя и непосредственно связанных соседей от хищника и вируса), Devorocyte (поглощение массы соседа).
- Пищу субстрата поглощает только фагоцит; связанные клетки обмениваются энергией с сохранением общей массы. Кератиноцит защищает себя и непосредственно связанных соседей от хищника и вируса.
- Движение, простое разделение пересекающихся клеток, обмен веществ, деление, старение, голодание, мутации в радиационной зоне, заражение. Пространственная сетка ограничивает поиск соседей.
- До 20 000 живых клеток. При лимите деление откладывается; попытка нового размещения возвращает ошибку. Это защитный лимит, не гарантия 30 Hz на любом устройстве. Производительность рендерера и симуляции в рамках переноса интерфейса не оптимизировалась.
- Параметры среды, инструменты удаления/подпитки/переноса, отдельная стерилизация; полное состояние мира сохраняется с состоянием генератора случайности, связями и геномами клеток. Восстановление проверяет данные до замены текущего мира.

Типы вдохновлены [Cell Lab Types](https://cell-lab.fandom.com/wiki/Types), но биофизика и баланс — упрощённая собственная модель. **Это частичная веб-адаптация, не полная копия Cell Lab.** Остальные 12 типов, полная кампания, азот/токсины/сигналы, программируемые параметры и расширенное создание чашки ещё не перенесены. «Хаос» и мультиплеер намеренно не реализованы. GPU compute и SharedArrayBuffer также не добавлялись.

## Структура и границы

- `crates/simulation/src/`: `genome.rs` (архетипы и ABI генома), `terrain.rs` (карта), `components.rs` (ECS-компоненты), `simulation/` (WASM API, fixed-step системы, пространственная сетка, связи и тесты). Rust не зависит от DOM или React; тот же крейт исполняется нативным сервером.
- `crates/protocol/`: общий контракт JSON-команд и бинарного формата чанков.
- `crates/server/`: авторитарный сервер на axum/tokio, публичные комнаты, WebSocket и раздача `dist/`.
- `frontend/simulation.worker.ts`: локальный режим — очередь команд, загрузка WASM, часы и перенос снимков на главный поток.
- `frontend/net/`: WebSocket-клиент, бинарный протокол и предсказанная сцена для сетевого режима; `OnlinePanel.tsx` — лобби и публичные комнаты.
- `frontend/model.ts`: контракт команд и представление генома в UI.
- `frontend/WorldView.tsx`: выбор бэкенда, повторный монтаж при сбое и принудительный переход на WebGL. `frontend/backend.ts`: начальный выбор WebGPU и тип бэкенда. `frontend/RendererToggle.tsx`: прежний технический переключатель, больше не подключён к игровому интерфейсу. `RustWorldView.tsx`: камера, hit testing и отрисовка; биология остаётся в Worker.
- `crates/frontend/src/web/`: прямой wgpu-рендерер (`backend.rs`, `labels.rs`, `gpu.rs`, `renderer.rs`, `repaint.rs`, `mod.rs`), GPU-буферы, resize и освобождение ресурсов. `scene_data.rs`: подготовка инстансов связей и native-тесты.
- `crates/frontend/src/scene.wgsl`: инстансинг клеток и связей, SDF-оформление, карта и подписи. egui/eframe не используются.
- `frontend/main.tsx`: переключение стартового экрана и лаборатории.
- `frontend/game/`: стартовый экран, лаборатория, связь с симуляцией, условия испытаний, среда, настройки и библиотеки.
- `frontend/editor/GenomeEditor.tsx` и `GenomePreview.tsx`: редактор режимов и изолированный предпросмотр развития.
- `docs/architecture.md`: ABI, порядок систем, сетевое расширение и ограничения.

Исходная C++/Emscripten-заготовка (`CMakeLists.txt`, `src/main.cpp`, `web/shell.html`, `scripts/build.sh`) сохранена как legacy и не участвует в новом запуске.
