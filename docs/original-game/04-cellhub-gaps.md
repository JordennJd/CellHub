# 04. Что переносить в CellHub и в каком порядке

Сравнение выполнено по исходникам коммита `0313a71`. Браузерная проверка POC в этот сеанс не выполнялась. «Есть» ниже означает наличие реализации в прочитанном коде, а не независимое подтверждение качества игрового опыта.

## Текущий путь POC

`frontend/main.tsx` сразу открывает единую лабораторию. Игрок видит карту, выбирает «Поместить / Выбрать / Переместить», меняет геном справа, запускает время и читает диагностику. Есть пустое состояние, пример с 60 клетками и пример многоклеточного организма. Отдельного меню кампании, учебного маршрута и библиотеки экспериментов в этом интерфейсе нет.

Конкретные источники:

- [main.tsx](../../frontend/main.tsx): интерфейс, сохранение, загрузка, выделение, применение генома, транспорт, примеры.
- [model.ts](../../frontend/model.ts): типы клеток, поля режима, максимум 40 режимов, сериализация генома.
- [simulation.worker.ts](../../frontend/simulation.worker.ts): команды управления симуляцией.
- [lib.rs](../../crates/simulation/src/lib.rs): мир, питание, возраст, условия деления, reset.

## Матрица соответствия

| Функция оригинала / цель игрока | Состояние CellHub по коду | Разрыв и значение для игрока |
| --- | --- | --- |
| J1: обучение действием | Есть объясняющие подписи и примеры; нет последовательности учебных шагов | Новичок не получает гарантированного первого успешного цикла |
| J2: выбор задачи, цель, прогресс | Нет каталога испытаний и условий победы | Нет внешнего смысла эксперимента и маршрута освоения новых механик |
| J3: вставка, наблюдение, время | Есть размещение, пауза, один шаг, 1×/2×/4× | Основа цикла уже существует; настройку и поведение скоростей нужно валидировать в игровом сценарии |
| Настройка среды | Есть переключение визуальных слоёв биомов/света/пищи/радиации; мир задан кодом | Переключение слоя не изменяет среду. Игрок не может поставить собственный контролируемый эксперимент |
| Инструменты микроскопа | Размещение, выбор, перемещение камеры | Перемещение камеры не равно Optical tweezers; boost/removal отсутствуют в прочитанном наборе команд |
| Диагностика | Тип, масса, возраст, поколение, изменения генома, связи; есть сводные рождения/смерти/заражения | Нет резерва азота, токсинов и части оригинальных показателей; сначала нужен ответ «почему клетка растёт/не делится/погибла» |
| Режимы и дочери | 1–40 режимов, создание/копия/удаление, два дочерних режима, доля массы, угол | Каркас развит; не следует заменять его простой коллекцией типов |
| Начальный режим отдельно от редактируемого | Команда spawn использует текущий `mode` редактора | Просмотр другого режима меняет режим новой вставки; отдельного `Initial` в модели нет |
| Адгезия | Связать A/B, наследование прежних связей для каждой дочери | Назначение сходно, но точное соответствие физике оригинала не проверено |
| Углы и цвет | Один angle; цвет берётся из типа, отдельных углов дочерей и RGB нет в Mode | Часть выразительности оригинального конструктора потеряна |
| Условия деления | `can_divide`, `mass >= threshold`, лимит популяции | В оригинальной справке ещё есть минимальный возраст 30 мин и формулировка превышения порога. POC не реализует эту возрастную задержку |
| Предпросмотр развития | Статическая карточка типа и строка M → A/B | Нет просмотра организма во времени до помещения в мир |
| Справка по настройке | Есть текст о типе и несколько пояснений | Нет систематической контекстной справки о причинах и эффектах параметров |
| Save genome / Gene Bank | Один ключ `cellhub.genome.v2` в localStorage с fallback v1 | Сохранения заменяют один слот; нет имён, библиотеки, экспорта и сравнения вариантов |
| Save plate / продолжить | В прочитанном интерфейсе и командах нет сохранения мира | Закрытие страницы не даёт обещания продолжить эксперимент |
| «Взять геном клетки» | Выбор клетки вызывает inspect и загружает её геном в редактор | Осмотр перезаписывает текущий черновик; копирование и наблюдение связаны неявно |
| «Применить к живой клетке» | Есть отдельная кнопка edit для выбранного id | Это подтверждённая возможность POC, но аналогичная операция оригинала в исследовании не установлена |
| Сброс | «Очистить» отправляет reset без подтверждения; пример также сбрасывает мир | Нужна явная семантика и защита результата на длинных экспериментах |
| Пропавшая клетка | Есть сообщение о делении/гибели и просьба выбрать потомка | Полезное состояние уже предусмотрено; автоматическое слежение не реализовано здесь |

Временные шкалы также различаются: в оригинале показаны часы/минуты, в POC — секунды. Нельзя переносить число «30 минут» как 1800 секунд без решения о масштабе симуляции и игровом темпе.

## Предлагаемый порядок разработки

Это рекомендуемый план, а не утверждённый список работ. P0 означает основу полноценного цикла, P1 — следующий слой, P2 — расширения после проверки основы. Сроки не оцениваются до уточнения реализации.

### W1 · P0. Устойчивый цикл эксперимента

**Пользовательская история:** я могу подготовить среду, поместить организм, увидеть развитие и понять результат, чтобы изменить одну гипотезу и повторить.

Состав: явное состояние паузы; базовые параметры света/питания; видимый активный инструмент; выделение и диагностические причины; предсказуемый reset с объяснением последствий. Зависимость: текущая симуляция POC.

**Критерии приёмки:**

1. В паузе помещение одной клетки увеличивает число клеток ровно на один; время не продвигается от самого просмотра панелей.
2. Изменение выбранного параметра среды отображается и действительно влияет на симуляцию; смена визуального слоя отдельно не меняет значения.
3. Для подготовленного контрольного генома в подходящей среде наблюдается рост и деление; в неподходящей — объяснимая нехватка ресурса.
4. Выделение показывает актуальный объект; после его исчезновения UI сообщает, что произошло или что точная причина неизвестна.
5. Reset имеет документированный результат для популяции, среды, времени, черновика генома и сохранений.

### W2 · P0. Явная модель редактирования генома

**История:** я могу исследовать клетку и редактировать конструкцию, понимая, какой объект изменяю.

Состав: различить черновик, режим для вставки, выбранную клетку и сохранённую запись; отдельно копировать геном из клетки; оставить явное применение к клетке, если это часть дизайна веб-версии. Зависимость: W1.

**Критерии приёмки:**

1. Простая диагностика другой клетки не уничтожает несохранённый черновик.
2. Начальный режим для новых клеток не меняется от просмотра настроек другого режима.
3. Перед применением ясно указано, меняются будущие вставки, выбранная клетка или библиотечная запись.
4. Ссылки дочерей после удаления режима остаются валидными; результат переназначения объясняется игроку.
5. В пользовательском тексте последовательно сопоставлены Android `mode` и веб-«архетип»; игрок не принимает их за разные сущности.

### W3 · P0. Возвращение к результату

**История:** я могу назвать организм и эксперимент, закрыть игру и продолжить работу.

Состав: библиотека именованных геномов; сохранение мира; загрузка; экспорт/импорт; явные ошибки. Нужна отдельная спецификация полей и версии форматов, без обещания совместимости с Android-файлами до изучения формата. Зависимости: F1, F7, W2.

**Критерии приёмки:**

1. Два генома с разными именами сохраняются независимо; загрузка одного не удаляет другой.
2. После перезагрузки страницы восстановлены заявленные параметры среды, время и клетки; объём гарантии описан в формате сохранения.
3. Геном и эксперимент имеют разные названия действий и не подменяют друг друга.
4. Несовместимый или повреждённый файл даёт понятную ошибку без уничтожения текущей сессии.
5. Существующая версия POC `cellhub.genome.v2` либо мигрируется, либо предлагается явный способ переноса.

### W4 · P1. Обучение на первой удачной гипотезе

**История:** без внешней инструкции я понимаю, зачем нужен геном и как он влияет на жизнь в чашке.

Предлагаемая последовательность: осмотреть чашку → поместить готовый Photocyte в освещённую область → запустить → увидеть рост/деление → изменить один параметр → сравнить → сохранить. Затем отдельное упражнение на две дочерние роли и адгезию. Это новый веб-сценарий, не реконструкция непроверенных шагов Android Tutorial I/II.

**Критерии приёмки:** каждый шаг имеет понятную цель и проверяемое событие завершения; есть повтор инструкции, пропуск и возврат; управление доступно мышью и касанием; ошибка размещения даёт путь исправления. Измерять начало и завершение шагов, время до первой вставки и первого деления, запросы помощи и точки выхода. Целевые значения назначать после тестов с новичками, а не выдумывать заранее.

### W5 · P1. Предпросмотр развития и объяснения

**История:** я вижу ожидаемую форму организма до рискованного эксперимента.

Состав: отдельная тестовая среда предпросмотра, возраст, старт/сброс, выделение режимов, справка о параметрах. Зависимость: W2; нужен согласованный уровень сходства предпросмотра и реального мира.

**Критерии приёмки:** изменение возраста предпросмотра не меняет мир; простые контрольные геномы дают объяснимую структуру потомков; условия предпросмотра показаны; у параметров есть эффект, единицы и ограничения; ошибки генома видны до вставки.

### W6 · P1. Небольшая кампания

**История:** каждое испытание знакомит с новым способом решения задачи и даёт ясный следующий шаг.

Состав: каталог задач, Objective с текущими значениями, Hint/Spoiler, завершение, награды, блокировки и повтор. Сначала небольшой набор задач на уже проверенной модели, а не весь список Android. Зависимости: W1–W4.

**Критерии приёмки:** победа и награда выдаются один раз; повторная попытка не стирает историческое прохождение; заблокированный уровень объясняет prerequisite; вставки и потомки считаются отдельно; после провала можно перезапустить и сохранить удачный геном.

### W7 · P2. Расширение выразительности и лабораторных инструментов

Отдельные углы дочерей, цвет, ресурсы и резервы, точная адгезия, оставшиеся инструменты, поздние типы, сигналы и специализированные задачи. Перед реализацией каждой системы — конкретный пример оригинального организма, наблюдаемый результат и серия контрольных опытов.

Критерий перехода: система добавляет новую проверяемую стратегию или эксперимент, а не только ещё один переключатель. Паритет с оригиналом и намеренные отклонения фиксируются по каждой механике отдельно.

## Решения, которые ещё нужны проекту

| Вопрос | Рабочее предложение | Почему нельзя считать уже решённым |
| --- | --- | --- |
| Точная копия или наследник? | Сохранять понятность цикла и выразительность генома; численный паритет выделить отдельно | POC уже имеет другую карту, единицы, лимиты и модель |
| Сначала кампания или песочница? | Сначала W1–W3, затем один учебный сценарий | Кампания зависит от устойчивой симуляции и сохранений |
| Ограничивать ли гены прогрессом? | В обучении дозировать; политику свободной песочницы решить отдельно | Наблюдённый профиль оригинала не раскрывает всех правил |
| Редактирование живой клетки | Сохранить как явный лабораторный инструмент, если нужно продукту | В POC есть, паритет с Android не доказан |
| Совместимость Android-файлов | Пока не обещать | Форматы и версия сериализации не исследованы |

## Как проверять готовность, кроме наличия кнопок

Провести наблюдение за новичком: попросить вырастить популяцию, объяснить причину неудачи, изменить геном и сохранить результат. Фиксировать действия и затруднения без подсказок ведущего; затем проверить повторное открытие сохранения. Это проверяет понятность игрового цикла. Технические тесты отдельно проверяют сериализацию, инварианты симуляции и ограничения задач.
