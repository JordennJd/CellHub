# Cell Lab v103: пользовательские пути для переноса в CellHub

Дата исследования: **10 ноября 2026**. Статус: проверенный срез основных путей, не полная спецификация всех испытаний и клеточных механизмов.

## Для чего этот комплект

Зафиксировать, что игрок пытается сделать, какие решения принимает, как игра отвечает на действия и какие результаты сохраняются. Это основа проектирования веб-версии, а не предложение скопировать Android-вёрстку.

Начинать разработку удобно с пути J3 «Создать → наблюдать → диагностировать → изменить → повторить» и требований W1–W4. Кампания и обучение строятся поверх этого цикла.

## Как читать достоверность

- **Наблюдение** — экран или переход действительно открыт в установленной игре; указан номер E, соответствующий скриншоту.
- **Справка игры** — утверждение прочитано во встроенном объяснении. Это свидетельство задуманного правила, но не независимое измерение симуляции.
- **Код POC** — поведение установлено чтением текущих исходников CellHub; браузерный прогон в это исследование не входил.
- **Предложение** — рекомендуемое поведение веб-версии. Не выдаётся за поведение оригинала или уже согласованный объём разработки.
- **Не проверено** — нужен дополнительный проход. Нельзя считать требование восстановленным по одному названию кнопки.

## Исследованная конфигурация

Android Cell Lab **Version 103** подтверждена экраном About [E39](evidence/39-about.png). Запуск выполнен через `start-cell-lab.sh` из корня родительского проекта. Эмулятор — `cell_lab_api28`, Android 9; кадры — 720 × 1280, вертикальная ориентация, интерфейс English.

Использован существующий профиль: Algae и Algae II **были пройдены до исследования**. В начале списка доступны Tutorial I, Tutorial II, Algae III и Macrophages; Macrophages II требует прохождения Macrophages. Это не чистый первый запуск. Новые награды в ходе исследования не получены.

Настройки влияют на поведение: `Ask before leaving lab` включена, `Ask before sterilize and reload` выключена, `Microscope slow motion` выключена. Эти значения нельзя объявлять заводскими настройками.

CellHub изучен по исходникам на коммите `0313a71`, прежде всего `frontend/main.tsx`, `frontend/model.ts`, `frontend/simulation.worker.ts` и `crates/simulation/src/lib.rs`.

## Связь с прежними материалами

[Обзор механик Cell Lab](../celllab-gameplay.md) остаётся справочным исследованием. Он объединяет Android, материалы PC-разработки и вторичные источники. В этом комплекте источник истины для наблюдаемого Android-поведения — скриншоты установленной v103.

Примеры уточнений: в Algae показаны два инструмента, а в эксперименте — пять; в исследованной конфигурации меню температуры содержит три пункта, без `Slow observe`; подтверждение очистки зависит от настройки. Эти факты не доказывают, что другие варианты интерфейса никогда не существуют.

## Подход к документации

Использована схема «цель → исходное состояние → действие → ответ игры → результат → восстановление после ошибки». Отдельные короткие документы связаны идентификаторами J (путь), S (экран), F (правило), W (предложение для веба), E (доказательство).

Разделение на игровые циклы, карту экранов и правила следует практическому подходу к живой дизайн-документации: фиксировать понятные команде решения и взаимодействия, поддерживать связи между разделами. [Game Developer: How To Write a Game Design Document](https://www.gamedeveloper.com/design/how-to-write-a-game-design-document).

Для будущего обучения предлагается измерять прохождение ключевых действий и учить смыслу игрового цикла, а не только расположению кнопок. Это соответствует рекомендациям по первому опыту игрока. [Roblox Creator Hub: Onboarding](https://create.roblox.com/docs/production/game-design/onboarding).
