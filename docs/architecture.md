# Архитектура v0.1

## Владение состоянием

Главный поток владеет React, камерой и отдельным WASM WorldRenderer (wgpu + WGSL). Worker единолично владеет WASM Simulation и hecs::World. UI посылает команды, а не изменяет ECS. React передаёт снимки через set_frame и камеру/слой/выделение через set_view. Rust владеет requestAnimationFrame, вызывает render сам и рисует только canvas; редактор и все HTML-панели сохранены в React. При загрузке приложение пытается запустить WebGPU, при недоступности или ошибке принудительно переключается на WebGL2 (GL-бэкенд wgpu) и блокирует кнопку WebGPU в UI. Две кнопки WebGPU/WebGL позволяют выбирать бэкенд вручную; перезагрузка страницы повторяет попытку WebGPU. Если недоступны оба, интерфейс показывает ошибку.

ECS-компоненты: Position (координаты, ориентация), Cell (внешний ID, текущий режим, масса, возраст, поколение, мутации, cooldown), Genome (один или несколько слотов без заданного верхнего лимита). Массив участков субстрата — глобальный ресурс, не сущности. Многоклеточный организм — связная компонента графа адгезии. Граф хранится в Rust как упорядоченное множество пар стабильных внешних ID клеток; каждое ребро неориентированное и уникальное.

Шаг 1/30 с: восстановление пищи → стабильный обход клеток по ID → питание/метаболизм/радиация/движение/планирование делений и смертей → локальные взаимодействия → удаление родителей и погибших → рождение потомков → перенос/удаление связей → решение механических ограничений. Деление сохраняет массу на момент деления; metabolism и потери при хищничестве намеренно рассеивают массу. Пища выражена в условных единицах, а не физически калиброванной концентрации.

## ABI

`spawn(x,y,mode,genome)`, `edit(id,mode,genome)`, `advance(steps)`, `reset()`, `snapshot()`, `links()`, `terrain()`, `stats()`, `genome(id)`, `cell_mode(id)`.

Геном содержит один или несколько слотов по 12 float32: `[kind, threshold, childA, childB, ratio, speed, angleRadians, lifespanSeconds, canDivide, bindChildren, keepAdhesionA, keepAdhesionB]`. Имена слотов сохраняются в JSON редактора и не меняют числовой ABI симуляции. Флаги имеют значения строго 0/1. Слоты и типы индексируются с нуля. Нефинитные значения, неверная длина, типы, флаги и ссылки на отсутствующих потомков отклоняются; непрерывные параметры ограничиваются в Rust. Циклические ссылки допустимы. Старый ABI (ровно 64 числа, 8 × 8) принимается с `canDivide=true` и тремя выключенными флагами связей; `genome()` всегда возвращает новый формат.

`links()` — `Uint32Array` пар `[cellIdA, cellIdB]`, отдельный от float-снимка клеток. Worker передаёт его в каждом кадре с transfer list. Рендерер получает его третьим аргументом `set_frame(cells, terrain, links)`. Rust сопоставляет ID с позициями за O(N + E), формирует по шесть float32 на связь (два конца и два ID) и рисует их одним instanced draw. Выделяется связь с выбранной клеткой; пустой массив удаляет все линии. WebGPU и WebGL2 используют один и тот же снимок и один рендерер.

При делении прежний конец каждого ребра заменяется на всех потомков, у которых включено наследование связей. Если делятся оба конца, применяется декартово произведение их наследников. Новая связь A–B добавляется только по `bindChildren`. Смерть удаляет инцидентные рёбра; reset очищает весь граф. Изменение генома живой клетки меняет правила её будущих делений, сохраняя существующие связи.

После перемещения выполняются 12 проходов позиционных ограничений: расстояние между связанными клетками стремится к сумме радиусов + 2 единицы, поправка распределяется обратно пропорционально массам. Это передаёт движение жгутика остальным клеткам. Связанные пассивные клетки самостоятельно не движутся; жгутик сохраняет направление без случайного поворота. У свободных клеток прежняя модель движения. Угловая жёсткость и передача ресурсов через связи не реализованы; при сложной плотной топологии и у границ ограничения решаются приближённо.

Снимок клеток — Float32Array, stride 10:

| Offset | Поле |
| --- | --- |
| 0 | внешний ID |
| 1–2 | x, y |
| 3 | радиус отрисовки |
| 4 | тип текущего режима |
| 5 | масса |
| 6 | возраст в секундах |
| 7 | поколение |
| 8 | число мутаций/заражений |
| 9 | ориентация в радианах |

Субстрат — 48 × 48 × 4 float32, построчно: `[light, radiation, food, biome]`. Статистика: `[tick, population, births, deaths, infections]`. Births включает размещённые клетки и обоих потомков; deaths не включает родителей при делении.

wasm-bindgen копирует снимки из линейной памяти WASM; Worker передаёт JS ArrayBuffer через transfer list без дополнительного копирования при postMessage. Это **не zero-copy из WASM и не SharedArrayBuffer**. При работающей симуляции частота снимков (включая граф связей) — до 30 Гц; на паузе снимки отправляются только после команды, изменившей мир. Камера и выбор остаются интерактивными без новых снимков; при паузе команды всё равно обрабатываются. До четырёх секунд модельного времени за один advance, но обычный таймер ограничивает входящий wall-clock delta до 250 мс. После фоновой паузы вкладка не пытается наверстать всё время.

## Сетевой режим

Опциональный multiplayer реализован по server-authoritative модели: `crates/server`
владеет `Simulation` и публичными комнатами, а браузеры подключаются по WebSocket.
Команды `spawn`/`edit`/`inspect`/`reset` валидируются на сервере; геном редактора
остаётся локальным и передаётся только вместе с конкретной командой. Сервер на каждом
тике рассылает **один** чанк карты (6 × 6 чанков, полный круг 36 тиков), а не весь мир.
Клиент между чанками предсказывает движение и связи, но любой пришедший чанк безусловно
перезаписывает свои клетки. Формат, протокол и ограничения: [multiplayer.md](multiplayer.md).

Фиксированный шаг, внешние монотонные ID, seed PRNG и сортировка обхода по ID остаются
полезными для воспроизводимости, но кроссплатформенный lockstep не гарантируется:
float32, sin/cos и различия native/WASM не проверяются как детерминизм между машинами.
Авторитетен только серверный снимок.

## Производительность и дальнейшая работа

Пространственная сетка использует ячейки 32 единицы и 3 × 3 соседства; контактный радиус 24. В плотных скоплениях остаётся квадратичный худший случай. В hot path 20 000 клеток больше нет `BTreeMap`-бакетов, `HashSet`-мусора и пересборки/сортировки списка сущностей каждый тик: сетка хранится плоским переиспользуемым массивом, а новые ID только дописываются в конец. Нативный бенчмарк: `cargo run --release -p cellhub-simulation --example bench 20000 60`. Для дальнейшей оптимизации обмена данными — пул/двойной буфер снимков, понижение частоты неизменных данных карты. SharedArrayBuffer имеет смысл после измерений и потребует secure context, COOP/COEP и протокола синхронизации Atomics.

Canvas рисуется в Rust напрямую через wgpu (WebGPU или WebGL2) и WGSL. egui удалён. Карта, подписи, связи и клетки требуют до четырёх draw call; клетки используют общий квадрат и instance buffer с исходным stride 40 байт. Terrain хранится в текстуре 48×48 `Rgba32Float`, потому что WebGL2 не поддерживает storage-буферы. В локальном режиме симуляция остаётся на CPU в отдельном Worker; в сетевом её исполняет нативный сервер. Интерфейс редактора — прежние HTML/React-контролы поверх canvas. Проверены цикл M1/M2/M3, GPU-пиксели связей и выделения, загрузка 20 000 клеток, один шаг и принудительный WebGL2. Это функциональные проверки, не бенчмарк FPS. Лимит 20 000 — ограничение модели, не измеренная производительность.

## Сохранение редактора

`cellhub.genome.v2` хранит JSON `{version: 2, modes: Mode[]}`. Загрузка проверяет типы, диапазоны и ссылки; при отсутствии v2 читает `cellhub.genome.v1` и добавляет значения по умолчанию для новых флагов. Сохранение содержит все архетипы, в том числе неиспользуемые. Это не снимок мира. Удаление архетипа перенумеровывает ссылки; ссылки непосредственно на удалённый архетип переходят к следующему, а при удалении последнего — к предыдущему. Копирование перенаправляет ссылки на самого себя к новой копии.
