# Архитектура v0.1

## Владение состоянием

Главный поток владеет React, камерой и PixiJS. Worker единолично владеет WASM Simulation и hecs::World. UI посылает команды, а не изменяет ECS. При ошибке загрузки нет скрытой JS-симуляции: интерфейс показывает ошибку.

ECS-компоненты: Position (координаты, ориентация), Cell (внешний ID, текущий режим, масса, возраст, поколение, мутации, cooldown), Genome (от 1 до 40 архетипов). Массив участков субстрата — глобальный ресурс, не сущности. Многоклеточный организм — связная компонента графа адгезии. Граф хранится в Rust как упорядоченное множество пар стабильных внешних ID клеток; каждое ребро неориентированное и уникальное.

Шаг 1/30 с: восстановление пищи → стабильный обход клеток по ID → питание/метаболизм/радиация/движение/планирование делений и смертей → локальные взаимодействия → удаление родителей и погибших → рождение потомков → перенос/удаление связей → решение механических ограничений. Деление сохраняет массу на момент деления; metabolism и потери при хищничестве намеренно рассеивают массу. Пища выражена в условных единицах, а не физически калиброванной концентрации.

## ABI

`spawn(x,y,mode,genome)`, `edit(id,mode,genome)`, `advance(steps)`, `reset()`, `snapshot()`, `links()`, `terrain()`, `stats()`, `genome(id)`, `cell_mode(id)`.

Геном — 1–40 архетипов по 12 float32: `[kind, threshold, childA, childB, ratio, speed, angleRadians, lifespanSeconds, canDivide, bindChildren, keepAdhesionA, keepAdhesionB]`. Флаги имеют значения строго 0/1. Архетипы и типы индексируются с нуля. Нефинитные значения, неверная длина, типы, флаги и ссылки на отсутствующих потомков отклоняются; непрерывные параметры ограничиваются в Rust. Циклические ссылки допустимы. Старый ABI (ровно 64 числа, 8 × 8) принимается с `canDivide=true` и тремя выключенными флагами связей; `genome()` всегда возвращает новый формат.

`links()` — `Uint32Array` пар `[cellIdA, cellIdB]`, отдельный от float-снимка клеток. Worker передаёт его в каждом кадре с transfer list. Отрисовка соединяет позиции двух концов и выделяет связи выбранной клетки.

При делении прежний конец каждого ребра заменяется на всех потомков, у которых включено наследование связей. Если делятся оба конца, применяется декартово произведение их наследников. Новая связь A–B добавляется только по `bindChildren`. Смерть удаляет инцидентные рёбра; reset очищает весь граф. Изменение генома живой клетки меняет правила её будущих делений, сохраняя существующие связи.

После перемещения выполняются 12 проходов позиционных ограничений: расстояние между связанными клетками стремится к сумме радиусов + 2 единицы, поправка распределяется обратно пропорционально массам. Это передаёт движение жгутика остальным клеткам. Связанные пассивные клетки самостоятельно не движутся; жгутик сохраняет направление без случайного поворота. У свободных клеток прежняя модель движения. Угловая жёсткость и передача ресурсов через связи не реализованы; при сложной плотной топологии и у границ ограничения решаются приближённо.

Снимок клеток — Float32Array, stride 10:

| Offset | Поле |
| --- | --- |
| 0 | внешний ID |
| 1–2 | x, y |
| 3 | радиус отрисовки |
| 4 | тип текущего режима |
| 5 | масса |
| 6 | возраст в секундах |
| 7 | поколение |
| 8 | число мутаций/заражений |
| 9 | ориентация в радианах |

Субстрат — 48 × 48 × 4 float32, построчно: `[light, radiation, food, biome]`. Статистика: `[tick, population, births, deaths, infections]`. Births включает размещённые клетки и обоих потомков; deaths не включает родителей при делении.

wasm-bindgen копирует снимки из линейной памяти WASM; Worker передаёт JS ArrayBuffer через transfer list без дополнительного копирования при postMessage. Это **не zero-copy из WASM и не SharedArrayBuffer**. Частота снимков (включая граф связей) — 30 Гц; при паузе команды всё равно обрабатываются. До четырёх секунд модельного времени за один advance, но обычный таймер ограничивает входящий wall-clock delta до 250 мс. После фоновой паузы вкладка не пытается наверстать всё время.

## Подготовка к сети

Фиксированный шаг, отдельные команды, внешние монотонные ID, seed PRNG, сортировка обхода по ID и независимый снимок отделяют модель от транспорта. Тест проверяет повторяемость одинакового запуска в одном runtime. **Кроссплатформенный lockstep не гарантируется:** используются float32, sin/cos и непроверенные различия native/WASM.

Следующий практический сетевой этап — авторитетный сервер: обёртка команд `{version, tick, playerId, sequence, command}`, валидация владения, применение на назначенном тике, подтверждения и снапшоты/дельты. Затем сериализация полного мира (включая RNG, поколения, cooldown, пищу и next_id), журнал команд, replay-тесты, интерполяция на клиенте. В текущем Worker команды применяются FIFO на границе очередной итерации; журнал, tick stamping и сетевой транспорт ещё отсутствуют.

Float32 точно представляет целочисленные ID только до 2^24. Для долгоживущего сетевого мира ABI нужно перевести на отдельный Uint32Array для ID/метаданных; текущий прототип рассчитан на короткие локальные эксперименты.

## Производительность и дальнейшая работа

Пространственная сетка использует ячейки 32 единицы и 3 × 3 соседства; контактный радиус 24. В плотных скоплениях остаётся квадратичный худший случай. Render строит Graphics для клеток; следующий шаг для больших популяций — Sprite/ParticleContainer или instanced mesh, пул/двойной буфер снимков, понижение частоты неизменных данных карты. SharedArrayBuffer имеет смысл после измерений и потребует secure context, COOP/COEP и протокола синхронизации Atomics.

WebGL — базовый renderer PixiJS. `?webgpu` позволяет запросить WebGPU, но не переносит симуляцию на GPU. Интерфейс редактора — доступные HTML-контролы поверх canvas. Всплывающие ошибки видны пользователю.

## Сохранение редактора

`cellhub.genome.v2` хранит JSON `{version: 2, modes: Mode[]}`. Загрузка проверяет типы, диапазоны и ссылки; при отсутствии v2 читает `cellhub.genome.v1` и добавляет значения по умолчанию для новых флагов. Сохранение содержит все архетипы, в том числе неиспользуемые. Это не снимок мира. Удаление архетипа перенумеровывает ссылки; ссылки непосредственно на удалённый архетип переходят к следующему, а при удалении последнего — к предыдущему. Копирование перенаправляет ссылки на самого себя к новой копии.
