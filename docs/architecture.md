# Архитектура v0.1

## Владение состоянием

Главный поток владеет React, камерой и отдельным WASM WorldRenderer (wgpu + WGSL). Worker единолично владеет WASM Simulation и hecs::World. UI посылает команды, а не изменяет ECS. React передаёт снимки через set_frame и камеру/слой/выделение через set_view. Rust владеет requestAnimationFrame, вызывает render сам и рисует только canvas; редактор и все HTML-панели сохранены в React. При загрузке приложение пытается запустить WebGPU, при недоступности или ошибке принудительно переключается на WebGL2 (GL-бэкенд wgpu) и блокирует кнопку WebGPU в UI. Две кнопки WebGPU/WebGL позволяют выбирать бэкенд вручную; перезагрузка страницы повторяет попытку WebGPU. Если недоступны оба, интерфейс показывает ошибку.

ECS-компоненты: Position (координаты, ориентация), Cell (внешний ID, текущий режим, масса, возраст, поколение, мутации, cooldown), Genome (один или несколько слотов без заданного верхнего лимита). Массив участков субстрата — глобальный ресурс, не сущности. Многоклеточный организм — связная компонента графа адгезии. Граф хранится в Rust как упорядоченное множество пар стабильных внешних ID клеток; каждое ребро неориентированное и уникальное.

Шаг 1/30 с: восстановление пищи → стабильный обход клеток по ID → питание/метаболизм/радиация/движение/планирование делений и смертей → локальные взаимодействия → удаление родителей и погибших → рождение потомков → перенос/удаление связей → решение механических ограничений. Деление сохраняет массу на момент деления; metabolism и потери при хищничестве намеренно рассеивают массу. Пища выражена в условных единицах, а не физически калиброванной концентрации.

## ABI

`spawn(x,y,mode,genome)`, `edit(id,mode,genome)`, `advance(steps)`, `reset()`, `snapshot()`, `links()`, `terrain()`, `stats()`, `genome(id)`, `cell_mode(id)`.

Геном v3 кодируется как `[-3, modeCount, ...modes]`. Каждая строка режима содержит 19 float32: `[kind, threshold, childA, childB, ratio, speed, angleRadians, lifespanSeconds, canDivide, bindChildren, keepAdhesionA, keepAdhesionB, childAngleA, childAngleB, mirrorA, mirrorB, red, green, blue]`. RGB — либо три значения 0…1, либо все −1 для цвета типа. Флаги строго 0/1; индексы с нуля. Имена режимов хранятся в метаданных библиотеки. Невалидные ссылки, значения и заголовки отклоняются. Принимаются старые строки v2 по 12 чисел и legacy 8 × 8; отсутствующие углы/зеркальность получают нули, цвет — автоматический. Явный заголовок устраняет неоднозначность длины между версиями.

`links()` — `Uint32Array` пар `[cellIdA, cellIdB]`, отдельный от float-снимка клеток. Worker передаёт его в каждом кадре с transfer list. Рендерер получает его третьим аргументом `set_frame(cells, terrain, links)`. Rust сопоставляет ID с позициями за O(N + E), формирует по шесть float32 на связь (два конца и два ID) и рисует их одним instanced draw. Выделяется связь с выбранной клеткой; пустой массив удаляет все линии. WebGPU и WebGL2 используют один и тот же снимок и один рендерер.

При делении прежний конец каждого ребра заменяется на всех потомков, у которых включено наследование связей. Если делятся оба конца, применяется декартово произведение их наследников. Новая связь A–B добавляется только по `bindChildren`. Смерть удаляет инцидентные рёбра; reset очищает весь граф. Изменение генома живой клетки меняет правила её будущих делений, сохраняя существующие связи.

После перемещения выполняются 12 проходов позиционных ограничений: расстояние между связанными клетками стремится к сумме радиусов + 2 единицы, поправка распределяется обратно пропорционально массам. Это передаёт движение жгутика остальным клеткам. Связанные пассивные клетки самостоятельно не движутся; жгутик сохраняет направление без случайного поворота. У свободных клеток прежняя модель движения. Перед каждым шагом связанные клетки обмениваются массой: поток вычисляется из начальных масс и нормируется по степени узлов; изменения применяются одновременно с сохранением суммарной массы. Угловая жёсткость не реализована; при сложной плотной топологии и у границ ограничения решаются приближённо.

Снимок клеток — Float32Array, stride 12:

| Offset | Поле |
| --- | --- |
| 0 | внешний ID |
| 1–2 | x, y |
| 3 | радиус отрисовки |
| 4 | тип текущего режима |
| 5 | масса |
| 6 | возраст в секундах |
| 7 | поколение |
| 8 | число мутаций/заражений |
| 9 | ориентация в радианах |

Поля 10 и 11 снимка: RGB как целое `0xRRGGBB` (−1 для цвета типа) и зеркальность 0/1. Первые десять полей сохраняют прежнее значение. Независимые углы дочерей задаются относительно направлений наружу от плоскости деления; зеркальность наследуется через XOR и меняет знак геометрии следующих делений. Минимальный возраст деления — 0,5 с веб-симуляции. Это ускоренная адаптация наблюдённого условия оригинала, а не заявление об общей эквивалентности временных единиц.

Субстрат — 48 × 48 × 4 float32, построчно: `[light, radiation, food, biome]`. Статистика: `[tick, population, births, deaths, infections]`. Births включает размещённые клетки и обоих потомков; deaths не включает родителей при делении.

wasm-bindgen копирует снимки из линейной памяти WASM; Worker передаёт JS ArrayBuffer через transfer list без дополнительного копирования при postMessage. Это **не zero-copy из WASM и не SharedArrayBuffer**. При работающей симуляции частота снимков (включая граф связей) — до 30 Гц; на паузе снимки отправляются только после команды, изменившей мир. Камера и выбор остаются интерактивными без новых снимков; при паузе команды всё равно обрабатываются. До четырёх секунд модельного времени за один advance, но обычный таймер ограничивает входящий wall-clock delta до 250 мс. После фоновой паузы вкладка не пытается наверстать всё время.

## Подготовка к сети

Фиксированный шаг, отдельные команды, внешние монотонные ID, seed PRNG, сортировка обхода по ID и независимый снимок отделяют модель от транспорта. Тест проверяет повторяемость одинакового запуска в одном runtime. **Кроссплатформенный lockstep не гарантируется:** используются float32, sin/cos и непроверенные различия native/WASM.

Следующий практический сетевой этап — авторитетный сервер: обёртка команд `{version, tick, playerId, sequence, command}`, валидация владения, применение на назначенном тике, подтверждения и снапшоты/дельты. Сериализация полного мира уже есть; для сети остаются журнал команд, replay-тесты между клиентами и интерполяция. В текущем Worker команды применяются FIFO на границе очередной итерации; журнал, tick stamping и сетевой транспорт ещё отсутствуют.

Float32 точно представляет целочисленные ID только до 2^24. Для долгоживущего сетевого мира ABI нужно перевести на отдельный Uint32Array для ID/метаданных; текущий прототип рассчитан на короткие локальные эксперименты.

## Производительность и дальнейшая работа

Пространственная сетка использует ячейки 32 единицы и 3 × 3 соседства; контактный радиус 24. В плотных скоплениях остаётся квадратичный худший случай. Для дальнейшей оптимизации обмена данными — пул/двойной буфер снимков, понижение частоты неизменных данных карты. SharedArrayBuffer имеет смысл после измерений и потребует secure context, COOP/COEP и протокола синхронизации Atomics.

Canvas рисуется в Rust напрямую через wgpu (WebGPU или WebGL2) и WGSL. egui удалён. Карта, подписи, связи и клетки требуют до четырёх draw call; клетки используют общий квадрат и instance buffer с исходным stride 48 байт. Terrain хранится в текстуре 48×48 `Rgba32Float`, потому что WebGL2 не поддерживает storage-буферы. Симуляция остаётся на CPU в отдельном Worker. Интерфейс редактора — прежние HTML/React-контролы поверх canvas. Проверены цикл M1/M2/M3, GPU-пиксели связей и выделения, загрузка 20 000 клеток, один шаг и принудительный WebGL2. Это функциональные проверки, не бенчмарк FPS. Лимит 20 000 — ограничение модели, не измеренная производительность.

## Сохранение редактора

Именованная библиотека хранится в `cellhub.library.v1`: отдельные записи геномов и миров, импорт/экспорт, начальный режим и метаданные имён. Прежние одиночные ключи `cellhub.genome.v1/v2` мигрируют в отдельную запись без удаления оригинала. Геномы экспортируются с версией 3; библиотека принимает прежние поля v2 и нормализует их. Удаление режима перенумеровывает ссылки, а копирование перенаправляет самоссылки на копию.

Снимок мира имеет внешний JSON `{version:1, values:number[]}`. Внутренний числовой формат v3 хранит клеточные геномы, зеркальность, RNG, счётчики, время, связи, истощение пищи и девять параметров среды. Внутренние версии 1/2 мигрируют; восстановление сначала валидирует новый мир и лишь затем заменяет текущий. Команды reset/restore/export подтверждаются Worker по requestId, старые кадры не могут завершить более новую загрузку.

Среда: свет, пища, радиация, вязкость, старение, гибель на краю, только точечные мутации, гравитация и плотность. При выключенной гравитации плотность не вызывает дрейфа. В веб-модели плотность — логарифм относительной плотности жидкости: 0 нейтрально, положительное значение даёт всплытие, отрицательное — оседание. Это собственный согласованный масштаб, а не механическое копирование ползунков Android.
